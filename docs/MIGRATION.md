## Редиректы

Файл `deploy/redirects.csv` содержит все необходимые редиректы:
- Старые URL → новые URL
- Статус 301 (постоянный редирект) для сохранения SEO

### Настройка редиректов в Nginx

После переключения DNS настроить редиректы в Nginx конфигурации:

```nginx
# Пример для /gorizontal
location = /gorizontal.html {
    return 301 /gorizontal;
}

location = /gorizontal/ {
    return 301 /gorizontal;
}

# Или использовать map для массовых редиректов
map $request_uri $redirect_uri {
    ~^/gorizontal\.html$ /gorizontal;
    ~^/vertical\.html$ /vertical;
    # ... и т.д.
}

if ($redirect_uri) {
    return 301 $redirect_uri;
}
```

Или использовать готовый скрипт для генерации конфига из CSV (создать при необходимости).

## Уведомление на старом сайте

Добавить баннер на старый сайт перед переключением DNS:

### Вариант 1: Внешний скрипт
```html
<script src="https://new.jaluzi-peterburg.ru/migration-banner.js" defer></script>
```

### Вариант 2: Inline скрипт
Скопировать содержимое `deploy/migration-banner.js` в `<head>` старого сайта.

Баннер:
- Появляется вверху страницы
- Ссылка на новый сайт
- Кнопка закрытия (запоминается в sessionStorage)
- Автоматически скрывается на новом сайте

## Возможные проблемы и решения

### Проблема: Потеря позиций в поиске
**Решение:** Убедиться, что все редиректы 301, sitemap отправлен, canonical URLs правильные.

### Проблема: Ошибки 404
**Решение:** Проверить redirects.csv, добавить недостающие редиректы в Nginx.

### Проблема: Формы не работают
**Решение:** Проверить CORS настройки, проверить API endpoints, проверить логи backend.

### Проблема: SSL ошибки
**Решение:** Проверить сертификаты Let's Encrypt, обновить если нужно.
