### ✅ Полностью готово

**Backend — архитектура:**

**Backend — API endpoints:**
- `GET /api/v1/pages` — список страниц
- `GET /api/v1/pages/{slug}` — страница с блоками
- `POST /api/v1/pages` — создать страницу (protected)
- `PUT /api/v1/pages/{id}` — обновить страницу (protected)
- `GET /api/v1/blocks?page_id={id}` — блоки страницы (protected)
- `POST /api/v1/blocks` — создать блок (protected)
- `PUT /api/v1/blocks/{id}` — обновить блок (protected)
- `DELETE /api/v1/blocks/{id}` — удалить блок (protected)
- `POST /api/v1/blocks/{id}/publish` — опубликовать блок (protected)
- `POST /api/v1/leads` — создать лид (public)
- `GET /api/v1/leads` — список лидов (protected)
- `PUT /api/v1/leads/{id}/status` — изменить статус (protected)

**Backend — авторизация:**
- JWT токены
- httpOnly cookie для хранения токена
- Auth middleware для protected endpoints
- Login endpoint с rate limiting (5 попыток / 15 минут)
- Логирование входов

**Frontend — базовая структура:**

- Структура папок (app/, components/, lib/)

**Frontend — авторизация:**

- Редирект на логин при отсутствии авторизации

**Frontend — CMS компоненты:**

**Frontend — блоки контента:**

**Frontend — страницы:**

## 4. УЗКИЕ МЕСТА (Bottlenecks)

1. **Inline-CMS UX неудобен**
   - Нет визуальной обратной связи
   - Нет состояний (saving, error, dirty)
   - Непонятно, что происходит при редактировании
   - **Блокер:** нельзя реально использовать редактор

2. **Нет контента на страницах**
   - Страницы пустые или с дефолтным HTML
   - Нет реальных блоков в БД
   - **Блокер:** нельзя показать сайт

3. **Неполные блоки**
   - Только 3 блока вместо 8+
   - Нет PriceBlock, ColorsBlock, GalleryBlock
   - **Блокер:** нельзя собрать страницу услуги

4. **Нет форм заявок**
   - Нет компонентов форм
   - Нет валидации
   - **Блокер:** нет механизма сбора лидов

5. **Валидация отсутствует**
   - Backend не валидирует входные данные
   - Frontend не валидирует формы
   - **Риск:** можно сломать данные через API

## 5. ВЫВОДЫ

### 📍 Текущая точка проекта

**Проект находится на этапе:** Завершена архитектура и инфраструктура, начата реализация inline-CMS, но редактор неудобен для реального использования, контент отсутствует.

### 🚧 Блокирующие проблемы

1. **Inline-CMS неудобен** — нет состояний, визуальной обратной связи, непонятен UX
2. **Нет контента** — страницы пустые, нет блоков в БД
3. **Неполные блоки** — только 3 блока, нужны PriceBlock, ColorsBlock, GalleryBlock, FAQBlock
4. **Нет форм** — нельзя собирать заявки с сайта
5. **Нет валидации** — риски целостности данных

### ▶️ Следующий ОДИН логичный шаг

**ЭТАП 2: Доработка UX inline-редактора**

**Цель:** Сделать редактор удобным для реального использования владельцем бизнеса.

**Результат:**
- Понятные состояния (view/edit/selected/dirty/saving/error)
- Визуальная обратная связь (подсветка, labels, индикаторы)
- Удобная публикация (подтверждение, статусы)
- Работает стабильно без глюков

**Почему это следующий шаг:**
- Без удобного редактора нельзя добавлять контент
- Без контента нельзя тестировать остальное
- Это критический блокер для всей CMS

**После этого:** Добавление блоков и контента станет осмысленным.
